# C# projects

The `csharp` ecosystem approximates what Rust guarantees at compile time with the strictest compiler and analyzer
settings the .NET SDK offers: no unsafe code, nullable references, checked arithmetic, every warning an error, banned
APIs, reproducible restore. The rules are `CSH-001..018` (see [generated rules](../rules/generated/csh.md)); all are
`proposed` until a second project has used them (ADR 4).

The first project measured is INI-Korrektur (Elementar Provisioning: a WPF tool for provisioning analyzers, .NET 10,
`local-only`). It passes every measurable `CSH` rule; its build settings are where rules 007..018 come from.

The second project is itsmesm (an ASP.NET Core API host, .NET 10, xUnit v3, `hosted-db`). It follows the template and
passes every measurable `CSH` rule (`baseline check`: CSH-001..005 and 007..018 pass, CSH-006 is manual). Where it had
to go beyond the template is written down below: [test projects](#test-projects) and
[hosted backends](#hosted-backends). The levels stay `proposed`: moving them is a separate change with a fleet run
(ADR 4) and the owner's decision, which itsmesm tracks as
[miralem-cebic/itsmesm#116](https://github.com/miralem-cebic/itsmesm/issues/116).

## Adopt it

1. `baseline.json`: `"ecosystems": ["csharp"]` and a topology. A hosted API without browser content (ASP.NET Core,
   Azure Functions) also sets `"surface": "api"` (ADR 7).
2. Copy `templates/csharp/` to the solution root: `Directory.Build.props`, `Directory.Packages.props`,
   `BannedSymbols.txt`, `global.json`, `.editorconfig`. Merge by hand when the project has them already.
3. Move every `Version=` from the `.csproj` files into `Directory.Packages.props`.
4. Restore once (`dotnet restore`) and commit the generated `packages.lock.json` files; restore with `--locked-mode`
   from then on.
5. Add test projects as described under [Test projects](#test-projects).
6. Name the local gate in `CLAUDE.md` and run it before every commit:

```bash
dotnet build MyApp.slnx -c Release                 # zero warnings, they are errors
dotnet test --solution MyApp.slnx
dotnet format MyApp.slnx --verify-no-changes
```

## What each rule is made of

| Rule | Setting or file |
|---|---|
| CSH-001, 002, 003, 004 | `Nullable`, `TreatWarningsAsErrors`, `AnalysisLevel` `latest-all`, `EnforceCodeStyleInBuild` |
| CSH-005 | `Directory.Packages.props` with `ManagePackageVersionsCentrally` |
| CSH-007, 008, 009 | `AllowUnsafeBlocks` `false`, `CheckForOverflowUnderflow`, `MSBuildTreatWarningsAsErrors` |
| CSH-010, 011 | `BannedApiAnalyzers`, `BannedSymbols.txt` with `DateTime.UtcNow`, `Task.Result`, `Task.Wait` |
| CSH-012, 013 | `RestorePackagesWithLockFile`, `NuGetAudit` + `NuGetAuditMode` `all` |
| CSH-014, 015 | `global.json`: `sdk.version`, `test.runner` |
| CSH-016, 017, 018 | no blanket `NoWarn`, a `[*.cs]` section in `.editorconfig`, `dotnet format --verify-no-changes` in the gate |

`templates/csharp/` is itself tested: `test/csharp-rules.test.js` requires that a project built from the template passes
every `CSH` rule and that each rule fails when its setting is flipped.

## Test projects

`CSH-015` puts tests on Microsoft.Testing.Platform, which makes every test project an executable. The strict settings
then collide with test code in three places. Measured on itsmesm with xUnit v3 (`xunit.v3.mtp-v2`); taking out any one
of the fixes fails the build.

| Symptom | Cause | Fix |
|---|---|---|
| `RS0030` in `XunitAutoGeneratedEntryPoint.cs`: `TaskAwaiter<TResult>.GetResult()` is banned | xUnit generates a synchronous `Main` that blocks on a task; the `CSH-011` ban applies to generated code too | define `XUNIT_GENERATED_DISABLE_WARNINGS` in test projects; it silences that file only |
| `CS1591` on every public test member | `GenerateDocumentationFile` (needed for `IDE0005`) plus warnings as errors | test section of `.editorconfig` (in the template) |
| `CA1515` on shared fixtures | in an executable, public types "could be internal"; test frameworks need public fixtures (the test classes themselves are exempt) | test section of `.editorconfig` (in the template) |

The `.editorconfig` section in `templates/csharp/` matches folders named `*.Tests` and everything below `tests/`. A test
project elsewhere needs its own glob. The xUnit part belongs in `Directory.Build.props`, with the version in
`Directory.Packages.props` (`<PackageVersion Include="xunit.v3.mtp-v2" Version="..." />`). The template does not choose a
test framework; MSTest and NUnit have not been measured.

```xml
<PropertyGroup Condition="$(MSBuildProjectName.EndsWith('.Tests'))">
  <OutputType>Exe</OutputType> <!-- xUnit v3 refuses to build without it -->
  <DefineConstants>$(DefineConstants);XUNIT_GENERATED_DISABLE_WARNINGS</DefineConstants>
</PropertyGroup>
<ItemGroup Condition="$(MSBuildProjectName.EndsWith('.Tests'))">
  <PackageReference Include="xunit.v3.mtp-v2" />
</ItemGroup>
```

## Hosted backends

`AnalysisLevel` `latest-all` includes `CA2007` (`ConfigureAwait`). It protects code that can run under a
`SynchronizationContext`: WPF, WinForms, libraries that others host. An ASP.NET Core or worker host has none, so
`ConfigureAwait(false)` adds noise without effect. Left on, the first adapter project in itsmesm fails with nine `CA2007`
errors. itsmesm sets `dotnet_diagnostic.CA2007.severity = none` under `[*.cs]` and writes the reason next to it.

The template leaves `CA2007` on, because its first project is a WPF app. A project whose code runs only in hosts decides
for itself and records why next to the setting; a blanket `NoWarn` is not the way (`CSH-016`).

A host that serves only an API declares `"surface": "api"` and sets the response headers of `HOS-009..012` in one
place: an `IFunctionsWorkerMiddleware` (Azure Functions, isolated worker), ASP.NET Core middleware with `UseHsts()`, or
`extensions.http.customHeaders` and `hsts` in the Functions `host.json`. Whether the host applies the `host.json`
settings depends on the hosting model; a request against the deployed function shows it.

## Not measurable with the current checks

- NuGet lock files exist per project (`src/App/packages.lock.json`). `GEN-014` only looks at the repository root, so a
  C# solution fails it although it is locked. `CSH-012` checks the setting instead.
- `win-x64` publish settings, device-specific banned APIs (serial ports, files, processes outside adapter projects) and
  fitness tests are project decisions, not baseline rules. INI-Korrektur keeps them in its own
  `BannedSymbols.Core.txt` and engineering-rules document.
- Design rules (value objects instead of primitives, `Result<T>` for expected errors, `sealed` by default, no static
  mutable state) are reviewed, not measured. `CSH-006` stays `manual`.
